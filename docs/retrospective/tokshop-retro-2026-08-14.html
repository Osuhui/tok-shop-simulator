三、关键决策复盘

几个「为什么这么做」而非「怎么做」的判断点。

① 引导第 2 步用「获得订单」而非 spec 的「上架开张」

《PLAYTEST_REPORT》P1-1 原文第 2 步是「上架开张」，但实现换成「获得第一笔订单」。这是有意偏差：初始库存默认 isListed=true（开局即可售），若单独列「上架」步骤会开局即完成、失去引导意义；故以「获得首单」作为更关键且可检测的早期目标（发货、升级都依赖先有订单）。已在 onboardingSteps.ts 顶部注释固化这一取舍。

② 8x = 3750ms/天，而非更快

没有盲目往上加 16x。spec P1-2 明确建议「约 3.75s/天」，8x 正好落在 30s→15s→7.5s→3.75s 的等比序列末端，节奏连续、不突兀。更快档位会让玩家来不及读每日结算弹窗，体验收益递减。

③ $500 奖励字段设为「可选」而非「必填」

最初加 onboardingRewardClaimed: boolean 为必填，立刻触发三处 TS 错误（测试夹具、存档序列化、旧存档）。改为可选 ?: boolean，!undefined === true 天然兼容「未发奖」语义，旧存档与测试零改动即过。这是「让字段缺省即安全」的小取舍。

④ 换行符用 .gitattributes 而非手动转换

本机 Windows 产生 CRLF 警告。没有逐文件转换（易引入噪声 diff），而是用 * text=auto eol=lf 让 Git 在 checkout 时归一，clean commit、无内容变化。
