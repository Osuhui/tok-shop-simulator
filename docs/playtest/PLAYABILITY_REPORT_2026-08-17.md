# TokShop Simulator · 可玩性报告 + 优化分析

> 评测视角：创作者/开发者自评 + 代码实测（非仅旧报告复读）
> 版本：v2.1.0 · 2026-08-17 当前 `main` 分支
> 文档目的：先回答"为什么你每次打开都不想玩、新手为什么不会玩"，再给出可落地的优化方案。

---

## 0. 一句话结论

**游戏已经"能玩、能通关、数值平衡"，但"不吸引人、且新手会在第一局卡死"。**
之前那轮试玩修复（修上架、重平衡、加引导浮层、加倍速）解决的是 **"功能/数值 bug"**，而你的真实体感是 **"入口断点 + 认知门槛 + 时间熬"**——这是另一类问题，旧修复没有碰到。

结论先行：**默认难度（normal）的新手在第一局会被卡在"开业了却永远没订单"的死胡同里**，且满屏 17 个专业术语面板，零基础玩家没有任何抓手。这解释了"打开就关掉"。

## 2. 核心可玩性问题（按严重度，附代码事实）

### 🔴 P0-1 默认路径新手死胡同：开业了却永远没订单

**复现路径（默认 entrepreneur / normal / UK）：**
1. `initNewGame` → 初始库存 3 件，但 `isListed=false`（`gameStore.ts:182`：`initiallyListed = getRequiredCertIds(...).length === 0`，normal 需 2 证 → false）。
2. 去「办证」申请 SELLER_VERIFY + RECEIVING_ACCOUNT，等待下发 → 店铺开业。
3. **开业后初始库存仍是 `isListed=false`**，没有任何代码在开业时自动上架。
4. 自然流量生成条件：`availableProducts = inventory.filter(i => i.quantity>0 && (i.isListed ?? false))`（`FinanceSystem.ts:124`）→ 为空 → **永远 0 自然订单**。
5. 看板的「新手第一步」清单只含 采购/获首单/发货/升级（`onboardingSteps.ts`），**没有"上架"步骤**；而"获得首笔订单"的提示写的是"等待自然流量或去达人"，**完全没提要先上架**。
6. 开业后「筹备开业」卡消失（`DashboardPanel.tsx:137` 条件变 false），**没有任何主动指引指向「上架」面板**。

**结果**：新手开业后干等，无订单，清单不推进，不知道自己卡在哪 → 关游戏。这正是"新手不知道怎么玩"的头号原因。

> 注：easy 难度 `initiallyListed=true`，所以 easy 玩家开局即有订单——**easy 才是真正"好玩"的路径，而默认选中却是 normal（断点路径）**（`MainMenu.tsx:63`）。

### 🔴 P0-2 "办证开业"仪式压在默认难度，把"卖货"挡在行政流程后

normal/hard 要求先办齐开业证件才能上架接单（`difficulties.ts:20`、`:28`；`OpeningSystem.ts:19`）。对老手是"仪式感"，对**默认新手是行政墙**：开局第一件事不是卖货，而是填表办证、等几天。第一局的"正反馈"被无限推迟。

### 🟡 P1-1 跨境术语墙，零基础无抓手

全程默认玩家懂 `回款周期 / 账期 / 健康分 / 合规 / 达人 / VAT / 承运商 / 在途` 等概念。没有：
- 术语悬停解释（KPI 卡、面板标题均无 tooltip）；
- 新手词典 / 速查；
- 任何"用大白话解释这是什么"的入口。
新手连"我为什么要去办证"都理解不了，更别说 VAT 稽查、品牌词罚款。

### 🟡 P1-2 17 个平铺导航，无阶段分组/优先级

`BottomNav.tsx:13-31` 列了 **17 个**入口（看板/选品/上架/达人/订单/物流/财务/店铺/税务/办证/员工/贷款/营销/承运商/存档/成就/数据）。旧试玩报告说"13 个太多"，现在更多了。没有"当前该用哪个"的优先级，新手像闯进没有导购的超市。

### 🟡 P1-3 时间驱动的"熬"循环，开局无即时正反馈

- 1x = 30 秒/天，早期自然流量稀疏（UK 6/天），首单要等若干天。
- 核心节奏是 等待→（偶尔操作）→等待回款，3D 办公室场景是**静态**的，没有 moment-to-moment 的参与感。
- "好玩"的部分（策略优化、达人博弈、合规权衡）只奖励**已经懂行**的玩家；零基础玩家在前几分钟只感到"在等"。

### 🟡 P1-4 第一局无叙事钩子，事件链被肝度门控

试玩报告称"事件/身份剧情链是灵魂"，但它在 `advanceOneDay` 里**概率/顺序触发**（`gameStore.ts:862-884`），第一局前几分钟几乎全是机械操作，没有一条立刻抓住人的故事线。新手的"第一课"是枯燥的行政而非故事。

### 🟢 P2-1 失败即惩罚，新手第一课是"被系统罚"

- 订单 2 天内不发货即取消 + 罚款 + 健康分下降（`gameStore.ts:495-522`，`deadline = day+2`）。
- 上架标题含品牌词直接罚款（`gameStore.ts:394`）。
新手往往在没理解机制前就被罚，第一印象是"这游戏在惩罚我"。

### 🟢 P2-2 "下一步"提示太弱，埋在看板里

"现在该做什么"只存在于 Dashboard 的清单和筹备卡，主屏（HUD/3D 场景）没有任何常驻的指路指针。

## 3. 为什么"bug 修好了还是不想玩"

| 旧试玩已修复 | 它解决了 | 它没解决（你的体感） |
|---|---|---|
| 上架机制失效 | 上架有意义了 | 默认路径开业后**根本不引导去上架** → 仍等于失效 |
| 通关数值失衡 | 能通关了 | 能通关 ≠ 想玩；新人卡在更早的"第一步" |
| 新手引导浮层 | 有 4 步文字 | 是**静态说明**，非"手把手带你卖出第一单" |
| 8x 倍速/跳天 | 能快进了 | 快进的是"等待"，没解决"我在等什么/为什么等" |
| 通关进度条 | 看得见目标 | 目标是一串数字，不是钩子 |

**本质**：上一轮把"能玩"做完了，但"好玩/会玩"需要的是**降低认知门槛 + 第一分钟就有正反馈 + 给新手一条不会卡死的路**。这正好是 P0-1/P0-2/P1-1/P1-3 覆盖的。

## 4. 优化分析（按优先级，可落地）

> 总原则：**不要动已验证的数值平衡（sim 27/27）；只改"入口、指引、可读性、首局节奏"。**

### 🔴 P0-1 修复：堵住默认路径死胡同（最高优先级，约 30 行改动）

**方案 A（推荐，最小改动）— 开业时自动上架初始库存**
在 `advanceOneDay` 检测到 `nowOpen && !wasOpen` 时（`gameStore.ts:843`），把**已存在的初始库存** `isListed` 置 true（它们是启动赠品，不是新采购）。新采购到的货仍默认未上架（需主动上架，保留仪式感）。
- 改动点：`gameStore.ts` 开业分支，对 `nextState.inventory` 里 `inboundQuantity===0`（即初始库存）的项置 `isListed=true`。

**方案 B — 把"上架"补进引导清单**
在 `onboardingSteps.ts` 增加 `list` 步骤（标题"上架开张"，panel:'listing'），并在其未完成时给 BottomNav 的「上架」红点（`BottomNav.tsx:46` 已有 `unlistedCount` 逻辑，可直接复用）。注意顺序：对 normal/hard 该步骤应排在"获首单"之前。

**立竿见影的兜底**：把 `MainMenu.tsx:63` 默认难度从 `normal` 改为 `easy`（easy 开局即有上架库存+可售），让第一次打开的人走"好玩"路径；normal/hard 留给回头客。

### 🔴 P0-2 修复：默认难度 fun-first

- **轻量方案**：normal 改成 easy 式的"先开业后补证"——`difficulties.ts` 把 normal 的 `requiredBeforeOpening` 设为 `[]`，办证降级为"开业后补办任务"（已有 grace 机制）。保留 hard 的严格封锁给硬核玩家。
- **更好方案（若想保留 normal 门槛）**：第一局用**脚本化新手向导**串起"办证→开业→上架→首单"，每一步在界面上**高亮对应按钮 + 一句指引**，而不是丢一个静态浮层。仅在首次游玩触发（`uiStore.onboardingSeen` 已有）。

### 🟡 P1-1 修复：拆掉术语墙

- 加一套**悬停 tooltip**：在 Dashboard 的 KPI 卡（资金/利润/待处理/健康分等）、各面板标题上，hover 显示大白话解释（如 健康分"低于 3 会限流，归零关店"）。
- 加一个「📖 新手词典」入口（设置或看板内），用 1-2 句话解释 回款周期/账期/VAT/达人/合规/承运商。
- 文件落点：新增 `components/ui/Tooltip.tsx` + `game/data/glossary.ts`，在 `DashboardPanel.tsx` / `KpiCard` 接入。

### 🟡 P1-2 修复：导航减负

- **分阶段导航**：把 17 个入口分成 3 组——「经营核心」（看板/选品/上架/订单/物流）、「成长」（店铺/员工/营销/达人/贷款）、「合规&系统」（税务/办证/承运商/财务/数据/成就/存档），默认只显示核心 5 个，其余收进「更多 ▾」。
- 或按 `shopLevel` 渐进解锁（员工 Lv.3、新区域等本就分级），未解锁的灰显不喧宾夺主。

### 🟡 P1-3 修复：第一分钟就有正反馈

- **种子首单**：开局自动上架后，第 1-2 天注入 1-2 笔"教学订单"并触发 💰 飘字，让玩家 60 秒内看到"卖出去了"的爽感。
- **加"加速到下一事件"按钮**：跳过空白等待，直接快进到"有订单/需发货/有事件"的那天。
- **压缩早期日长**：前 30 天用更短的 `SPEED_DAY_DURATION_MS`，让早期节奏更紧凑（不影响已验证的中后期平衡）。

### 🟡 P1-4 修复：第一局叙事钩子前置

- 进入游戏第 1 天就触发身份剧情链（`activeChainId` 已设）的**第一个具体 beat**，并带明确 CTA（如"回复创业导师的来信"），而不是等随机事件。让新手第一眼看到"这是个有故事的经营游戏"，而非"一堆数字面板"。

### 🟢 P2-1 修复：新手宽容期

- 前 3 天（或前 3 单）**免逾期罚款、免健康分扣减**，让玩家在"安全沙盒"里学机制；首单上架用"合规预检（只提示不罚款）"代替直接罚款。
- 落点：`checkOverdueOrders`（`gameStore.ts:495`）与 `checkAndListProduct` 罚款分支加 `day < GRACE_DAYS || ordersCompleted < 3` 豁免。

### 🟢 P2-2 修复：常驻指路指针

- 主屏 HUD 常驻一行「👉 现在去做：XXX」（来自当前未完成的最高优先级引导步骤），点击直接跳转对应面板。比埋在看板里的清单更显眼。

## 6. 验证建议

1. **别再只用 sim 验证**：sim 机器人"知道"要办证/上架，掩盖了新手断点。需新增 **"零基础首局 60 秒走通"** 的无头浏览器脚本（puppeteer 走 easy 默认路径，断言：开局→有订单→发货→回款 能在不读源码的情况下完成）。
2. **保留现有闸门**：tsc strict / Vitest / build / 平衡 sim 27/27 全部保持通过；任何改动不得破坏通关可达性。
3. **主观验收**：让一个**完全没玩过**的人（或不看代码）打开游戏，能否在 2 分钟内说出"我现在该干嘛"——能，才算修好 P0/P1。
