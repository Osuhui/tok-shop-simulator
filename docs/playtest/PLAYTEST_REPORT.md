# TokShop Simulator · 试玩心得（资深玩家视角）

> 评测人：资深模拟经营玩家（800+ 小时品类经验，含 Shopify / 跨境电商题材）
> 版本：v2.0.0 · Phase 0（React 19 + Three.js + Zustand + Vite）
> 试玩设定：辞职创业者 / 标准难度 / 英国（UK）
> 文档目的：从"好不好玩、好不好上手、值不值得玩下去"的玩家视角，给出结构化评测与可落地的优化清单。

---

## 一、一句话总结

一个**框架扎实、系统丰富**的跨境经营模拟器，但当前体验有三个"断点"：**上架机制形同虚设、通关目标数值失衡、新手缺乏引导**。它现在像一栋精装修但没通水电气的房子——你看得见野心，却住不进去。距离"好玩"只差关键的打磨三步。

---

## 二、核心玩法循环

```
选品采购（有在途时间）
   └─► 上架（编辑合规标题，避免品牌/绝对化/医疗违规词）
         └─► 等待订单：① 自然流量（按区域日活） ② 达人合作（成功率建模）
               └─► 48 小时内发货（扣运费，状态 shipped→inTransit→delivered）
                     └─► 平台账期 + 物流后回款（paid）
                           └─► 升级店铺 / 解锁区域 / 扩张（员工·营销·贷款·税务）
                                 └─► 应对合规事件（随机 + 身份剧情链）
                                       └─► 通关（店铺等级 + 净资产）或 破产（资金 < -$500）
```

逻辑自洽、层次清晰，是这份设计的加分项。

## 三、上手体验（第一局真实感受）

第一局最大的问题是——**"我不知道自己在干嘛"**：

1. 开局只有**一条欢迎通知**，把"采购→上架→发货"一句话塞给你，没有任何分步引导。
2. 我本能地点开「上架」，想给商品编辑标题。结果编辑完，**界面上没有任何地方显示"已上架"，订单却照常自己在冒**（见痛点 1）。我一度以为上架面板是坏的。
3. 底部导航 + 面板多达 **13 个**（选品、达人、上架、订单、物流、财务、店铺、税务、员工、贷款、营销、承运商、存档）。新玩家像闯进一家没有导购、没有指示牌的超市，每扇门后面都不知道该干什么。
4. 第一笔订单进来时我很兴奋，但发现它**不会主动提醒我发货**；等我两天后想起来，订单已经被取消 + 罚款，健康分还掉了——新手的第一课是"被系统惩罚"，体验很劝退。

## 四、数值与平衡（核心痛点）

### 🔴 痛点 1：上架系统完全失效（P0·严重）

- **代码事实**：`ListingPanel` 调用 `checkAndListProduct`，后者**只做违规词罚款，从不记录"已上架"状态**；而 `FinanceSystem.generateOrganicOrders` 生成自然流量订单时**只看 `inventory.quantity > 0`**，完全不看是否上架。
- **玩家后果**：从不打开上架面板，库存照样每天稳定出货；而一旦手贱填了含品牌词的标题，"检测并上架"反而扣你 $500 重罚。这个核心互动面板，**不做是赚、做错是亏、做对无收益**——纯纯的陷阱。
- **设计意图 vs 现状**：新手引导通知里明确写着"在『上架』中编辑标题"，说明设计是想让上架成为"开张营业"的仪式动作，但实现漏了这一步。

### 🔴 痛点 2：通关目标量级严重不匹配（P0·严重）

以**标准难度**为例：通关 = **Lv.8 + 净资产 $60,000**（365 天内）。

- 升级到 Lv.8 的硬门槛（来自 `getLevelUpRequirement`）：累计订单 **350 单** + 累计营收 **$21,000** + 累计升级费 **$13,500**。
- 但**净资产目标要 $60,000**。
- 按当前每单净利润约 **$15** 估算，350 单总利润仅约 **$5,250**，离 $60,000 差一个数量级。
- **结论**：达标 Lv.8 时净资产往往才几千美元，永远够不到 $60,000；而要堆到 $60,000 又需卖出数千单，远超 350 单门槛。两个条件**完全脱节**——稳健玩法几乎必败，只剩"极限刷达人单"一条险路。
- *（注：达人单量极大，UK 的 HomeVibe 单场 700 单、US 的 TrendDaddy 单场 5000 单，理论上可暴力拉净资产；但资金占用、备货、7 天冷却和成功率让这条路门槛极高且脆弱。）*

### 🟡 痛点 3：自然流量过薄 + 回款周期过长

- UK 日自然流量仅 **2**，声誉 50 时 +2 = **4 单/天**，每单 1–3 件。纯靠自然流量滚雪球极慢。
- 回款周期：UK = 14 天账期 + 7 天物流 = **21 天**，US 更长 **32 天**；采购在途还要 5–10 天。一个完整资金循环 UK 近 30 天，早期资金链极易断裂。

### 🟡 痛点 4：时间节奏与"熬"

- 1x = 30 秒/天，4x = 7.5 秒/天。365 天即便 4x 也要约 **46 分钟纯挂机**，中段还需手动发货/补货。缺乏"跳到次日"的快进，玩家中段容易疲惫。

## 五、UI / UX 评价

**做得好的**：
- 3D 办公室场景 + 霓虹 HUD 有氛围感；
- 特效飘字（💰 回款、📦 发货、⬆️ 升级）反馈爽快，正反馈及时；
- 通知系统、事件对话框叙事感强；
- 面板信息密度合理，不挤。

**待补的**：
- 没有"当前该做什么"的指引：订单面板不突出"待发货"，上架面板不显示"未上架商品"。
- 缺少**通关进度可视化**：玩家看不到"距离通关还差多少净资产 / 多少单"，目标感弱。
- 13 个面板平铺，没有按"经营阶段"分组（采购期 / 运营期 / 扩张期）。

---

## 六、爽点 / 亮点（值得保留的）

- **事件系统（随机 + 身份剧情链）是灵魂**：身份专属剧情线（创业者供应链 / 老手品牌化 / 学生校园）让重玩有动力；破产/通关有叙事收束，不像纯数值游戏。
- **达人合作的"成功率 + 订单量"建模有深度**：挑达人像在组卡组，匹配度、意愿、佣金博弈有意思。
- **合规风险有张力**：品牌词重罚、VAT 稽查、退货率，让"灰色操作"有代价，不是无脑挂机。
- 系统耦合设计干净（可插拔 `DayProcessor` 注册表），扩展性好——这对长期运营是加分。

## 八、优化建议（按优先级，可量化）

### 🔴 P0-1 修复上架机制（让"开张"有意义）
- `InventoryItem` 增加 `isListed: boolean` 与可选 `listedTitle`。**初始库存默认已上架**（用商品名，避免开局零订单）。**新采购到货默认未上架**。
- `generateOrganicOrders` 仅从 `isListed && quantity>0` 的库存生成自然流量订单。
- `checkAndListProduct` 合规通过时置 `isListed=true, listedTitle=title`；达人订单不受上架限制（达人自带流量）。
- `ListingPanel` 展示每个库存的**上架状态标签**（已上架/未上架），让"上架"成为开张仪式。

### 🔴 P0-2 重新平衡通关与数值（让目标可达）
- 让 Lv.8 与净资产目标**量级一致**：建议净资产目标随升级门槛等比设定，或下调到稳健可达区间（标准难度约 **$15,000–$25,000**）。
- 适度提高基础自然流量（UK 2→3~4，US 2→3~4，SEA 3→4~5），缩短回款账期（UK 14→10，US 22→16），让现金流更健康的滚雪球。
- **必须配套自动化模拟脚本**（见下节），用数据而非拍脑袋定参。

### 🟡 P1-1 新手引导（onboarding）
- 首次进入显示 4 步浮层：① 去选品采购 → ② 去上架开张 → ③ 等订单去物流发货 → ④ 攒钱升级店铺。完成给反馈。
- 复用 `TaskSystem` 骨架，增加 `task_onboard_*` 新手任务，在 Dashboard 显示进度。

### 🟡 P1-2 快进与倍速
- 底部加「⏭ 跳到次日」按钮（立即结算 1 天）。
- 增加 **8x** 倍速（约 3.75 秒/天）。

### 🟢 P2 提示与可视化
- Dashboard 顶部常驻「通关进度条：Lv.X/8 · 净资产 $Y / $Z · Day D/365」。
- 订单面板红点提示「待发货 N」；上架面板提示「未上架 M 件」。

### 难度校准（hard · 2026-08-14）

针对「hard 初始资金偏紧、清算线不友好」的已知风险做校准，让 hard 从极限生存回到「努努力能成」的可达成挑战，同时保留比 normal 明显的难度梯度。

- **改动（仅 hard 生效参数）**：`startGoldMultiplier` `0.8 → 0.9`（student / veteran / entrepreneur 起始资金分别约 $3,150 / $4,500 / $6,300）；目标 `day 300 → 330`、`shopLevel 10 → 9`、`netWorth $65,000 → $55,000`。
- **未动全局破产线**：破产判定 `gold <= -500` 为全局统一逻辑，easy / normal 已稳定通关，本次不加宽以免扩大改动面；若后续想更宽松可单独评估。
- **验证（headless sim，UK 区 9 配置 × 3 局）**：改动后仍为 **27/27 victory**，难度梯度健康 —— easy D41–71 / normal D72–129 / **hard D111–170**；hard 比 normal 晚达成 40–80 天、目标净资产高 $20k，但仍远早于 330 天上限，真人留有容错空间。

> **校准中挖出的技术债（待办）**：`difficulties.hard` 的 `blockOpening`（需四证齐全才开业）、`gracePeriodDays`、`penaltyMultiplier` 三字段**已在类型与配置中定义，却从未接进 `gameStore` 与模拟逻辑**——设计文档《Content_Design》描述的「hard 开业封锁 + 0 宽限 + 1.3 罚款」目前是 dead config，hard 的真实难度仅来自起始资金倍率与目标数值。这意味着：(a) 当前 hard 实际比设计意图宽松得多；(b) 若要真正兑现设计里的 hard 挑战，需把这三字段接进 `gameStore`（开业守卫 / 逾期罚款倍率），但那会显著加难，与本次「更可达」目标方向相反，故留作独立技术债跟踪。

### 关键决策：引导步骤偏离报告原文

报告 P1-1 建议的第 2 步是「去上架开张」，实现采用「获得第一笔订单」。这是**有意偏差**：初始库存默认 `isListed=true`（开局即可售），若单独列「上架」步骤会开局即完成、失去引导意义；故以「获得首单」作为更关键且可检测的早期目标（发货、升级均依赖先有订单）。已在 `onboardingSteps.ts` 注释固化。
